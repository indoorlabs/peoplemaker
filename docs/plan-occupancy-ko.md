# 공간 종류가 정해지면 — 재실자 · 시나리오 계획

spacemaker 가 "이 건물은 학교다 · 양로원이다" 를 정했을 때, 이쪽이 무엇을 더
낼 수 있는가. **계획만 적는다. 여기에 구현은 없다.**

---

## §0 먼저 경계 — 이 계획의 절반은 "안 하는 것" 이다

이 저장소는 배치·동선·활동 스케줄을 안 한다 (agents.md). "학교 시뮬레이션
셋팅" 은 그 금 위에 바로 걸치는 말이라, 금을 다시 긋는 것부터 해야 한다.

공간 종류가 정해지면 **두 가지**가 정해진다:

```
그 건물이 어떻게 생겼는가        →  spacemaker   (교실 24개 · 계단 3 · 복도 폭 2.4m)
그 안에 누가 어떻게 있는가       →  여기         (학생 · 교직원 · 각자 몸이 무엇을 하는가)
```

**사람에 관한 통계는 여기, 건물에 관한 것은 저기.** 사이즈코리아 치수를 여기
두기로 한 것과 같은 기준이다. "학급당 학생 수" 는 사람에 관한 규정이고,
"이 학교에 교실이 몇 개인가" 는 건물이다.

그래서 새로 만드는 것들이 지켜야 할 **네 가지 금지**가 먼저 있다. 이것이
없으면 이 계획은 spacemaker 를 두 벌 만드는 일이 된다:

1. **자리(x, z)를 안 만든다.** 지금 활동 층이 지키는 것과 같다.
2. **절대 시각을 안 갖는다.** "9시 수업 시작" 은 공간 쪽이 준다. 여기서 낼 수
   있는 것은 "이 활동 다음에 올 수 있는 활동" 과 "얼마 동안" 뿐이다.
   → 게이트가 프로필·일과에 `09:00` 같은 시:분이 있으면 **막는다.**
3. **방 이름을 안 갖는다.** `needs: 'seat'` 까지가 여기고, 어느 교실 몇 번
   자리인지는 저기다.
4. **못 하는 것을 조용히 대신하지 않는다.** 뛰는 클립 없는 팩에 대피를 안
   주는 규칙을 층이 올라가도 그대로 지킨다.

## §1 지금 있는 것으로 무엇이 되고 안 되는가 (2026-09-13 실측)

계획을 세우기 전에 셌다. 팩 9개(합성 기준 1 + Rocketbox 8), 클립 21~22종.

```
몸                     있는 것          없는 것
  어린이(초등)          2 (c01 · c02)
  어른                  6 (여2 · 남2 · 정장 2)
  청소년(중·고)         0   ←
  노인                  0   ←  Rocketbox 에 없다
  휠체어·보행보조       0   ←  CC0 자산이 없다 (2026-09-12 확인)
  교복·간호복           0   ←
```

클립 합집합 22종: `clap crouch documents door-knock door-open drink idle
listen look-around phone phone-call photo run sit sit-table stretch talk
walk-fast walk-forward walk-slow wave work-table`

이걸로 두 공간을 채워 보면:

```
학교 — 부족 3
  ✓ 수업 중 앉기(sit·sit-table) · 쓰기(work-table) · 발표(talk) · 듣기(listen)
  ✓ 복도 이동(walk·walk-fast·run) · 문(door-open) · 급식 줄서기(idle)
  ✗ 계단           ← 학교 대피의 지배 구간인데 0종이다
  ✗ 손들기         ← 수업 장면이 전부 같은 자세가 된다
  ✗ 청소년 몸      ← 중·고등학교는 배역이 아예 안 채워진다

양로원 — 부족 7. 지금은 **못 한다**
  ✓ 요양보호사(어른 팩으로) · 식사(drink) · 거실(sit · talk · listen)
  ✗ 노인 몸 · ✗ 휠체어 · ✗ 보행보조기
  ✗ 눕기/침대 · ✗ 앉았다 일어서기(전이) · ✗ 지팡이 보행 · ✗ 부축(2인)
```

**이 표가 이 계획의 결론을 이미 절반 말한다.** 학교는 자산 3개를 채우면
되고, 양로원은 소프트웨어가 아니라 **자산과 라이선스 결정**이 먼저다.

반대로 이미 있어서 바로 쓸 수 있는 것도 수로 적어 둔다 — 공간 쪽이 방을
맞출 때 쓰는 값들이다:

```
문 손잡이   어른 1.065~1.108m · 어린이 0.871~0.878m
의자 엉덩이 어른 0.591~0.610m · 어린이 0.467~0.500m
통행 폭     0.460~0.613m (maxWidthM) · 눈높이 1.330~1.683m
예산        4ms 에 8,327명 (먼 단계 0.1) · 3,623명 (0.25) · 스킨드 28명
```

인원으로 보면 **학교 규모는 이미 감당된다.** 벽은 성능이 아니라 가짓수다 —
학생 1,000명을 어린이 팩 2종으로 세우면 500명씩 똑같은 아이다. 몸 가짓수는
고정비(몸 하나당 0.042ms)라 여섯까지 싸다. 즉 **화면 품질의 벽은 코드가
아니라 자산 수**다.

## §2 층을 하나 더 올린다 — 클립 ← 활동 ← 일과

지금 구조가 이렇다:

```
클립      walk-forward · sit · talk        (팩이 갖고, 잰 값이 붙는다)
활동      meeting · goToRoom · evacuate    (클립의 차례 — src/lib/activity.mjs)
```

공간 종류가 요구하는 것은 그 위다. "학교" 는 활동 하나가 아니라 **활동의
차례**다: 수업 → 복도 이동 → 수업 → 급식 → …

그래서 **`src/lib/routine.mjs` (일과)** 를 같은 규약으로 한 층 더 쌓는다.
활동이 클립에 대해 한 일을, 일과가 활동에 대해 한다:

```js
export const ROUTINES = {
  schoolDay: {
    parts: {
      student: {
        start: 'inClass',
        states: {
          inClass:  { activity: 'lesson',   forS: 'until-cue', next: [['corridor', 1]] },
          corridor: { activity: 'goToRoom', forS: 'until-cue', next: [['inClass', 3], ['lunch', 1]] },
          lunch:    { activity: 'meal',     forS: 'until-cue', next: [['corridor', 1]] },
        },
      },
      teacher: { /* … */ },
    },
  },
};
```

**`forS: 'until-cue'` 가 기본이다.** 수업이 45분인 것은 학교가 정하지 몸이
정하지 않는다 — 공간 쪽이 `cue()` 로 알린다. 활동 층에서 "길 길이는 공간만
안다" 고 한 것과 똑같은 이유다.

새 활동도 함께 필요하다 (기존 4개 위에): `lesson`(수업 듣기) · `meal`(식사) ·
`rest`(거실에서 쉬기) · `care`(돌봄 받기) · `queue`(줄서기).

게이트(`check-routine`)가 볼 것:
- 막다른 일과 — 넘어갈 곳 없는 상태. 활동 층과 같은 검사다
- **시:분이 적혀 있으면 막는다** (§0 의 금지 2)
- 이 팩 묶음으로 이 일과가 되는가 — 안 되면 어느 활동의 어느 클립이 없는지
- 같은 씨(seed) 면 같은 차례가 나오는가

## §3 배역 (casting) — 누구를 어느 팩으로 세울 것인가

"양로원 재실자 100명" 을 받으면 누구를 어느 팩에 배정하는가. 지금은 그
물음에 답할 수 없다 — **카탈로그가 그 사람이 누구인지를 안 갖고 있다.**
`packId` 문자열(`rocketbox-c01`)과 클립의 `tags: ['male','child']` 로만
짐작할 수 있는데, 짐작은 이 저장소가 안 하기로 한 것이다.

### 계약에 더할 것: `catalog.person`

```json
"person": {
  "source": "declared-by-import",
  "ageBand": "child",        // child | youth | adult | older-adult
  "sex": "male",             // male | female | unspecified
  "mobility": "walk",        // walk | cane | walker | wheelchair
  "attire": "casual"         // casual | business | uniform | care-worker
}
```

**이것은 잰 값이 아니라 적은 값이다.** 그래서 출처를 `declared-by-import` 로
두어 `bodyDims` 의 `measured-from-pack` 과 갈라 놓는다. 손이 닿는 자리에서
"무엇에 닿는지는 사람이 적고, 언제 어디까지 뻗는지는 우리가 잰다" 로 나눈
것과 같은 규약이다.

**적힌 것과 잰 것이 어긋나면 게이트가 막는다.** 절대값이 아니라 관계로 본다:
`ageBand: 'child'` 인 팩의 키가 `adult` 인 팩들의 최솟값보다 커지면 막는다.
지금 팩으로 실제로 걸리는 규칙이다 (어린이 1.431·1.437 / 어른 1.732~1.810).

### 배역 API

```js
planCast(profile, { packs, count: 100 })
// → { assigned: [{ packId, n }], coverage: 0.18,
//     missing: [{ want: 'older-adult', n: 70, why: 'ageBand older-adult 인 팩이 0개' },
//               { want: 'wheelchair',  n: 12, why: 'mobility wheelchair 인 팩이 0개' }] }
```

`coverage` 를 **수로 낸다.** 양로원 프로필에 지금 팩을 넣으면 0.18 쯤이
나와야 맞다 (요양보호사만 채워진다). 그 수가 자산 로드맵이 된다.

## §4 용도 프로필 — "학교" 가 무엇을 뜻하는가

`profiles/school-kr.json` · `profiles/nursing-home-kr.json` 을 팩과 같은
자격으로 저장소가 갖는다 (계약이 검사하고, 게이트가 지킨다).

```json
{
  "id": "school-kr",
  "ko": "학교 (한국)", "en": "School (KR)",
  "composition": [
    { "role": "student", "share": 0.93, "ageBand": "youth",  "source": "…" },
    { "role": "staff",   "share": 0.07, "ageBand": "adult",  "source": "…" }
  ],
  "routine": "schoolDay",
  "scenarios": ["normal", "fire-drill"]
}
```

**비율에는 출처가 있어야 한다.** 인체치수와 완전히 같은 규약이다 — 출처·
연도·모집단이 없으면 `pending` 으로 남기고 게이트가 그 수를 센다. 0.93 을
어디서도 못 가져오면 **비워 두고 "공간 쪽이 준다" 고 적는다.** 후보 출처:
교육통계서비스(KESS), 「학교시설·설비기준」, 노인복지시설 현황(보건복지부).

### 그리고 §5 와 겹치는 값들

프로필은 사람의 **움직임 성질**도 요구한다 — 보행속도, 경보 후 움직이기까지
걸리는 시간. 이건 지금 저장소에 **한 건도 없다.**

`src/lib/occupancy.mjs` 를 `anthropometry.mjs` 와 같은 꼴로 둔다:

```js
export const OCCUPANT_VALUES = {
  walkingSpeedMps: {
    ko: '평지 보행속도',
    values: [ /* 출처가 붙은 것만 */ ],
    pending: 'SFPE Handbook / BS PD 7974-6 / 소방청 피난안전성평가 가이드라인에서 받아야 한다. 우리 클립에서 잰 값(어른 1.21 · 어린이 0.80m/s)은 이 애니메이션의 속도이지 모집단 값이 아니다',
  },
  preMovementTimeS: { /* 경보 후 반응 — 용도별로 크게 다르다 */ },
  stairSpeedMps:    { /* 계단. 대피 시간의 지배 구간 */ },
};
```

**우리 클립에서 잰 속도를 여기에 쓰지 않는다.** 어른 1.21m/s 는 Rocketbox
애니메이터가 만든 걸음의 속도이지 "한국 성인 보행속도" 가 아니다.
`bodyDims` 를 사이즈코리아와 갈라 둔 것과 정확히 같은 함정이다.

## §5 시나리오 — 무슨 일이 일어나는가

시나리오는 **cue 의 대본**이다. 시각도 방도 안 갖는다.

```json
{
  "id": "school-fire-drill",
  "profile": "school-kr",
  "seed": 20260913,
  "acts": [
    { "on": "cue:alarm",        "who": "all",             "switchTo": "evacuate" },
    { "on": "cue:east-blocked", "who": "group:east-wing", "switchTo": "evacuate", "note": "동쪽 계단이 막힌 경우" }
  ]
}
```

`on` 이 **시각이 아니라 cue 이름**인 것이 핵심이다. 언제 경보가 울리고 어느
문이 막혔는지는 공간 쪽이 안다. 여기는 "그 신호를 받으면 몸이 무엇으로
갈아타는가" 만 갖는다.

### 씨(seed) — 비교가 되려면 재현이 돼야 한다

건물을 고친 효과를 보려면 **같은 사람들이 같은 순서로** 움직여야 한다.
활동 층이 이미 씨를 받으므로(`startActivity({ seed })`), 시나리오의 씨
하나에서 사람마다의 씨를 뽑아 내려보내면 된다. 게이트가 "같은 씨 = 같은
차례" 를 매번 확인한다.

### preflight — 돌리기 전에 "이게 되는가" 를 한 장으로

`planActivity` 의 `missing` 을 시나리오 전체로 키운 것이다. 이게 이 계획에서
**가장 값이 나가는 물건**이라고 본다:

```
학교 화재 대피 · 프로필 school-kr · 팩 9개

  배역     학생 0% (ageBand youth 인 팩 0개) · 교직원 100%
  활동     evacuate ok · lesson 못 함 (손들기 클립 0)
  공간에게  문 손잡이 0.871~1.108m · 좌석 0.467~0.610m · 통행 폭 0.460~0.613m
  못 하는 것 계단 클립 0 — **계단 대피 시간은 낼 수 없다**
  예산     1,000명 · 먼 단계 0.25 · 몸 2종 → 4ms 안 (3,623명 여유)
```

마지막 줄이 중요하다. 걷는 대피를 조용히 내주지 않은 것과 같은 이유로,
**계단 없이 낸 학교 피난 시간은 거짓이다.** 그 사실을 결과 대신 내놓는다.

## §6 계약이 더 필요해지는 자리 (알아 둘 것)

이 계획을 실제로 하려면 지금 계약으로 안 되는 데가 셋 있다.

**1. 계단 — `rootMotion: 'travel'` 은 평지 가정이다.** 지금 `speedMps` 는
수평 속도이고, 계단 클립이 들어오면 그 값이 수평인지 경사면인지 갈린다.
새 잰 값이 필요하다: `riseMps`(수직 속도) · `riserM`(한 단 높이). 그리고
계단은 피난 시간의 지배 구간이라 P4(군중)의 **전제 조건**이다.

**2. 전이 클립과 섞어 넘기기.** 활동이 클립을 갈아탈 때 지금은 툭 끊긴다.
회의(앉아서 말하기⇄듣기)에서는 덜 보이지만, 양로원처럼 동작이 느린 데서는
그대로 보인다. 앉았다 일어서기 같은 **전이 클립**과, 이미 목록에 있던
"가까운 사람 섞어 넘기기(cross-fade)" 가 여기서 있으면 좋은 것이 아니라
**필요한 것**이 된다.

**3. 2인 상호작용 — 결정이 필요하다.** 부축·악수·마주보고 대화는 몸 둘의
**상대 자리**를 요구한다. 계약은 한 팩 = 한 사람이고 자리를 안 만든다.
두 몸 사이의 30cm 가 몸의 사실인가 공간의 사실인가 — 이건 내가 정할 것이
아니라 **물어볼 것**이다 (§9).

## §7 단계와 끝나는 조건

기존 계획(`plan-peoplemaker-ko.md` §3)의 P1 과 P4 사이에 들어간다.
**각 단계는 끝나는 조건이 수로 적혀야 끝난 것이다.**

| 단계 | 내용 | 끝나는 조건 |
|---|---|---|
| **O1** | `catalog.person` · 배역 (`planCast`) | 팩 9개에 person 이 붙고, 적힌 것과 잰 것이 어긋나면 게이트가 막는다. 양로원 coverage 가 **0.2 미만으로 정직하게** 나온다 |
| **O2** | 일과 층 (`routine.mjs`) · 활동 5종 추가 | 학교 하루가 활동 차례로 풀린다. 시:분을 적으면 게이트가 막는다. 막다른 일과 0건 |
| **O3** | 용도 프로필 2종 (학교·양로원) | 계약 검사를 통과하고, 출처 없는 비율이 **0건** (없으면 pending 으로 세어진다) |
| **O4** | `occupancy.mjs` — 보행속도·반응시간 | 값마다 출처가 붙거나 pending 수가 적힌다. 우리 클립 속도를 모집단 값으로 쓴 곳 0건 |
| **O5** | 시나리오 + preflight 한 장 | 같은 씨 = 같은 차례. 시나리오 하나가 "되는가/안 되는가" 를 수로 낸다 |
| **O6** | 자산 채우기 (청소년·노인·휠체어·계단·전이) | **라이선스 결정이 먼저다** (§9). 결정 전에는 O1~O5 가 "없다" 를 정확히 말하는 것이 성과다 |

**O1~O5 는 자산 없이 다 된다.** 그리고 그것들이 끝나면 양로원 시나리오가
"못 한다 · 무엇이 없다" 를 한 장으로 말하게 된다 — 그게 자산을 사거나 만들
근거가 된다. 순서를 이렇게 두는 이유다.

## §8 안 할 것

- **경로 탐색·문 배정·군중 회피.** JuPedSim/RVO2 는 P4 이고 공간 쪽 물건이다.
  여기서는 "그 사람이 지금 뛰고 있다" 까지만 낸다.
- **시간표.** 45분 수업도, 6시 저녁도 여기 안 적는다.
- **법정 피난안전성평가.** 우리가 내는 수는 **성능평가가 아니다.** 그
  문장을 시나리오 결과에 박아 둔다 — 안 박으면 언젠가 그렇게 쓰인다.
- **실측 재실 동선.** 학교 CCTV·요양시설 기록이 팩에 섞이면 개인정보다
  (기존 §5 위험 3). 섞였으면 그 사실이 카탈로그에 남아야 한다.

## §9 물어볼 것 — 내가 정하면 안 되는 셋

1. **CC-BY 를 받을 것인가.** 청소년·노인·휠체어·보행보조가 **전부** 여기
   걸린다 (2026-09-12 에 CC0 휠체어가 없다는 것을 확인했다). 받기로 하면
   ATTRIBUTIONS 자동 생성(기존 §5)을 같이 만들어야 한다. **양로원은 이
   결정 없이는 시작되지 않는다.**
2. **프로필을 누가 갖는가.** "학교 = 학생 93%" 를 이 저장소가 가질 것인가,
   spacemaker 가 갖고 여기는 배역·일과만 낼 것인가. 나는 사람에 관한
   통계이므로 여기라고 보지만, 건물 용도 분류를 이미 spacemaker 가 갖고
   있다면 두 벌이 된다.
3. **2인 상호작용의 경계** (§6-3). 부축을 넣으려면 몸 둘의 상대 자리를
   누가 갖는지부터 정해야 한다.
